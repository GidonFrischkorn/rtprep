`rtprep` is an R package at the root of this repository. It puts response
time screening, trimming, aggregation, EZ-diffusion estimation and data
generation with known contaminants behind one interface: every screening rule
returns the same per-trial columns (`.keep`, `.prob`, `.rule`, `.reason`),
whichever rule produced them.

## Package code (`R/`)

- `Imports` is `graphics`, `stats` and `utils`, and code under `R/` uses base
  R plus those. `dplyr`, `tibble`, `ggplot2`, `withr` and the other `Suggests`
  are for tests, vignettes and examples only; a call to one of them from `R/`
  is a finding, as is a new `Imports` entry without a stated reason.
- Screening functions take vectors and return data frames, so that they work
  inside `dplyr::mutate()` and `dplyr::reframe()` without requiring the
  tidyverse. A change that makes a data frame or a tidyverse object the
  required input breaks that.
- No `set.seed()` in package code. A seed inside an exported function makes it
  silently non-random for the caller.
- Generated files are regenerated, never hand-edited: `NAMESPACE` and `man/`
  come from `devtools::document()`, `README.md` from `README.Rmd` via
  `devtools::build_readme()`. An edit to a generated file without the matching
  change in its source is a finding. `DESCRIPTION` pins `RoxygenNote: 7.3.3`;
  a diff that rewrites unrelated `.Rd` files or adds a `Config/roxygen2`
  field means `document()` ran under another roxygen2 version.
- Exported functions have roxygen documentation with a runnable `@examples`
  block. A new screening rule cites the published algorithm it implements,
  with the DOI in its roxygen block.
- A change to what a rule returns (which trials it drops, `.prob`, a default
  value, a convergence setting) changes results people may already have
  reported. It needs a rationale in the pull request and a `NEWS.md` entry,
  and it normally arrives behind a new argument rather than by moving a
  default.

## Tests

- testthat edition 3. New behaviour comes with tests.
- `tests/testthat/test-equivalence.R` is the insurance for reimplementing
  published algorithms instead of depending on `trimr` and `bmm`. The `trimr`
  layer has a frozen fixture (`tests/testthat/fixtures/trimr-reference.rds`)
  plus a live comparison; the `bmm` layer is live only and skips when `bmm` is
  absent. Relaxing a tolerance, regenerating a fixture, or adding a skip to
  get these green, without establishing which implementation moved, is a
  finding.
- `tests/testthat/fixtures/screen-engine-reference.rds` freezes the engine's
  answers at the current defaults. Regenerating it is legitimate only together
  with a documented change of those defaults.
- A test of a substantive claim has to be able to fail. Comparing two code
  paths that share the helper under test, or asserting on a value the test
  itself computed the same way, proves nothing.
- Comparisons against other packages are wrapped in `skip_on_cran()`.

## Documentation and language

- Prose is en-GB (`Language: en-GB`); new technical words may need an entry in
  `inst/WORDLIST`.
- Terminology carries the package's argument, so documentation keeps it:
  - **contaminant** for a trial not generated by the decision process;
    **outlier** only for the statistical criterion or when citing literature
    that uses the word;
  - **screening** for any rule that classifies trials, **trimming** only for
    rules that remove them, **aggregation** for the summary-statistic step;
  - parameters are **drift**, **bound**, **ndt**, **zr**;
  - the contaminant processes are **leading-edge anticipations**, **delayed
    start-ups** and **informationless responses**.
- The documentation (`R/`, vignettes, articles, `NEWS.md`) stands on its own
  and does not point at material outside the repository;
  `.github/docs-decoupling-gate.R` enforces the specific patterns.

## Branches, versions and releases

| Branch | Cut from | Merges into | Method |
| --- | --- | --- | --- |
| `feat/*`, `fix/*`, `docs/*`, `test/*`, `chore/*` | `develop` | `develop` | squash |
| `release/X.Y.Z` | `develop` | `main` | merge commit |
| `hotfix/X.Y.Z` | `main` | `main` | merge commit |
| `sync/vX.Y.Z` | `develop`, then `git merge --no-ff origin/main` | `develop` | merge commit |

- `main` is what is on CRAN; `develop` holds reviewed work that is not.
- On `develop` the version is `X.Y.Z.9000` and `NEWS.md` starts with
  `# rtprep (development version)`. A release branch sets `X.Y.Z` and the
  release heading. A version bump anywhere else is a finding.
- `.github/rulesets/main-gate.json` and `develop-gate.json` require checks by
  name: the `R-CMD-check` matrix legs `ubuntu-latest (release)`,
  `macos-latest (release)`, `windows-latest (release)`, plus `test-coverage`
  and `branch-policy`. Renaming a job or matrix leg without updating both
  gate rulesets in the same pull request leaves every later pull request
  waiting for a check that never reports.

## What not to report

These are already enforced, or are not what a review is for:

- anything `R CMD check` reports (run on Linux, macOS and Windows for every
  pull request), including the spelling test in `tests/spelling.R`;
- test coverage numbers (`test-coverage` workflow);
- pure formatting that `styler` would change, and the two linters `.lintr`
  disables on purpose (`object_name_linter`, `object_usage_linter`);
- the source/target branch rules (`branch-policy` check) and the
  documentation patterns the decoupling gate scans for;
- problems that existed before the pull request.
